## 1. Executive Summary

This specification establishes the architectural standard for **Multi-Part Composite Assemblies**, **3D-Printable Subpart Deconstruction**, and **Universal Outward Normal Orientation** across all fabricated hardware components in the Open Biosphere catalog.

While RFC-0017 established baseline procedural mesh integrity and single-solid 2-manifold invariants, real-world robotic mechanisms frequently consist of articulated, interlocking, or multi-material assemblies (e.g., sliding die gates, optical deflectors, and spoke hubs). Prior to this RFC:
1. Multi-part assemblies were rendered as monolithic, single-color meshes, obscuring the mechanical relationship between moving plates, drive pinions, and structural rails.
2. Users seeking to 3D print or CNC machine individual subcomponents lacked standalone, watertight STL files for each individual sub-part.
3. Multiple catalog parts exhibited inverted face normal windings on internal features, concave pockets, and concentric caps.
4. Build platers were unavailable, requiring manual orientation and repositioning of disparate subparts before slicing.

RFC-0018 remediates these deficiencies by introducing:
* **glTF `COLOR_0` Per-Subpart Shading:** Embedding vertex color attributes to visually differentiate functional subparts within a unified WebGL canvas while preserving specular PBR lighting.
* **Composite Classification & Badge System:** Designating multi-part assemblies with `classification: "composite"`, `isComposite={true}`, and high-contrast HUD badges.
* **Standalone Watertight Subpart Models:** Generating independent 2-manifold `.stl` and `.gltf` assets for every individual sub-part.
* **Pre-Arranged Build Plater Models (`print.stl`):** Batching all assembly subparts grounded flat at `Z = 0.0 mm` within standard 220x220 mm FDM print envelopes.
* **Global CAD Normal Audit & Reconciliation:** Implementing recursive normal validation verifying 100% strictly outward normals across all 202 glTF models in the ecosystem.

## 2. Multi-Part Composite Assembly Architecture

### 2.1 Color Coding & Vertex Color Parsing
In composite mechanisms, functional clarity requires immediate visual distinction between stationary guides, kinetic members, and actuators. RFC-0018 mandates encoding subpart identities into glTF binary buffers via the standard `COLOR_0` attribute accessor (`componentType: 5126`, `VEC3` IEEE 754 floats):

```typescript
// ModelViewer.tsx client-side COLOR_0 extraction
if (prim.attributes && prim.attributes.COLOR_0 !== undefined) {
  const colAcc = jsonData.accessors[prim.attributes.COLOR_0];
  const colBv = jsonData.bufferViews[colAcc.bufferView];
  const colOffset = (colBv.byteOffset || 0) + (colAcc.byteOffset || 0);
  const stride = colAcc.type === 'VEC4' ? 16 : 12;

  for (let i = 0; i < colAcc.count; i++) {
    const cOffset = colOffset + i * stride;
    const r = Math.min(255, Math.max(0, Math.round(binView.getFloat32(cOffset, true) * 255)));
    const g = Math.min(255, Math.max(0, Math.round(binView.getFloat32(cOffset + 4, true) * 255)));
    const b = Math.min(255, Math.max(0, Math.round(binView.getFloat32(cOffset + 8, true) * 255)));
    vertexColors.push([r, g, b]);
  }
}
```

The WebGL rendering loop applies painter's depth sorting and specular lighting calculations directly to each subpart's color index, preserving backface culling and physical realism.

### 2.2 Standard Color Palette
Composite sub-assemblies follow standardized functional color allocations:
* **Structural Guide Frames & Casings:** Slate Gray (`#8c96a5`)
* **Horizontal Primary Actuation Elements:** Electric Blue (`#0ea5e9`)
* **Vertical Secondary Actuation Elements:** Golden Amber (`#f59e0b`)
* **Rotary Actuators & Drive Pinions:** Coral Orange (`#ef4444`)

## 5. 3D Printable Subpart Standards & Bed Grounding Invariants

Every fabricated part marked with `classification: "composite"` must supply both discrete sub-part models and a batch build plater satisfying the following geometric invariants:

1. **Standalone 2-Manifold Topology:** Each subpart file (`subpart-XX-name.stl`) must be a fully closed shell where every edge belongs to exactly two triangular faces (`non_two = 0`).
2. **True Positive Solid Volume:** Signed volume integration must confirm strictly positive enclosed volume:
   $$\text{Volume} = \frac{1}{6} \sum_{i=1}^{F} \mathbf{v}_{0} \cdot (\mathbf{v}_{1} \times \mathbf{v}_{2}) > 0$$
3. **Bed Grounding Invariant ($Z \ge 0.0\text{ mm}$):** All standalone STL subparts and batch plater models (`print.stl`) must translate coordinates such that the minimum vertical coordinate satisfies $\min(z) = 0.0\text{ mm}$. Slicers can directly generate G-code without manual Z-plane drops or raft compensations.
4. **Metadata Registry Binding:** `src/data/parts.json` must declare `"is_composite": true`, `"classification": "composite"`, and catalog all subparts with their respective filenames, colors, quantities, and download endpoints.

## 6. Global CAD Normal Audit & Reconciliation Suite

RFC-0018 incorporates the repository-wide normal reconciliation suite (`scripts/reconcile_all_cad_orientations.py`). The script evaluates the dot product between face unit normals $\mathbf{n}$ and vectors from the mesh centroid $\mathbf{c}$ to face centers $\mathbf{f}_c$:

$$\mathbf{n} \cdot (\mathbf{f}_c - \mathbf{c}) \ge 0$$

For multi-component assemblies or convex hulls, individual closed sub-solids are evaluated against component-level signed volume metrics.
