# RFC-0014: Interactive 3D Composite Assembly Standard

* **RFC ID:** `RFC-0014` (Supersedes `RFC-0010` & `RFC-0011` for machine manuals)
* **Author:** Documentation Systems, Technical CAD & Physical Assembly Engineering Team
* **Status:** `Implemented / Canonical Standard`
* **Target Classification:** Technical Illustration / CAD Systems / Interactive Visualization
* **Applicable Scope:** All 27 Machine Stage Manuals (`hardware/<machine-slug>/stage-{0,1,2}.mdx`), Global Part Registry, and Machine Overview Pages

---

## 1. Executive Summary & Problem Statement

Prior standards (`RFC-0010` and `RFC-0011`) established vector SVG blueprints as the canonical format for machine manuals. While vector line drawings provide resolution independence, 2D projections inherently suffer from severe physical assembly limitations:
1. **Blind Fastener & Reverse Obstruction:** 2D projections cannot be rotated in real time, concealing reverse fastener heads, T-nut channels, and blind clearance cavities.
2. **Kinematic Ambiguity:** Complex spatial linkages (such as dog clutch dog teeth, auger flights, scissor crawler linkages, and gantry carriage V-wheels) are difficult to comprehend from static orthographic or isometric cross-sections.
3. **Disconnected Part-to-Assembly Context:** Builders inspecting a static blueprint have to manually cross-reference 2D drawing callouts with separate 3D part registry downloads.

**RFC-0014** mandates that **all 2D static blueprints across machine stage manuals are completely replaced by interactive, client-side 3D models**. Full physical composite assemblies are procedurally synthesized from underlying sub-models, providing 360° orbit rotation, directional lighting, wireframe toggles, and zero-latency inspection.

## 3. Core Architectural Directives

### 3.1 Composite Assembly Synthesis
1. **Hierarchical Merging:** Machine stages are composed of discrete physical sub-models from the global part registry (`src/data/parts.json`).
2. **Spatial Alignment & Constraints:** Each sub-model is placed with exact Cartesian translational offsets ($dx, dy, dz$) and spatial rotations corresponding to its real-world mechanical mating datum.
3. **Unified Autodesk 3DS Chunk Pipeline:** Sub-model vertices (`0x4110`) and triangular face indices (`0x4120`) are compiled into a single optimized Autodesk 3DS binary container, eliminating external texture dependencies and multi-file network waterfalls.

### 3.2 1:1 Stepwise 3D Model Invariant
1. **Part 4 (Stage Assembly):** Every machine stage manual features an interactive `<ModelViewer>` loading the complete composite 3D assembly (`/open-biosphere/assets/machines/<slug>/stage-<N>.3ds`).
2. **Part 5 (Step-by-Step Execution):** Each individual assembly step (`### Step X.Y`) renders the interactive 3D sub-model of the component being installed, with its live material properties, fabrication classification, and unit cost badges.
3. **Final Step Integration:** The final step of each stage displays the completed stage assembly seated in its mounting fixtures.

### 3.3 Zero-Overhead Performance & Visibility Gating
1. **`client:visible` Mounting:** All 3D viewers leverage Astro's `client:visible` hydration directive, preventing DOM instantiation until the user scrolls near the component.
2. **`IntersectionObserver` Render Throttling:** Each active canvas observes its own viewport intersection; when offscreen, the internal `requestAnimationFrame` render loop pauses automatically.
3. **Decoupled Animation Loop:** Continuous orbital rotation is tracked via mutable reference counters (`rotYRef`), preventing React re-render cascades and achieving sustained 60 FPS performance across multiple viewers.
