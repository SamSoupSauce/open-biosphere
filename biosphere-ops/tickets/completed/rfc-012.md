# RFC-012: Concrete Custom-Fabricated Part Contracts & Subpage Architecture

## 1. Problem Statement

Previously, custom-fabricated assemblies and non-standard interfaces were handed off to automated tooling (`agy`) or stage documentation as open-ended, unresolved notes (e.g., "figure it out" comments or generic adapter placeholders). This breaks deterministic BOM rollup, stalls mechanical planning, and creates ambiguities in downstream assembly protocols.

## 2. Specification & Directives

### 2.1 Elimination of Ambiguous Placeholders

* Every required custom element (e.g., custom solar cone collector brackets, duckweed overflow weir adapters, manifold junctions, servo linkages) must be declared as a discrete, named entity conforming to the RFC-008 shareable parts schema.
* Vague comments, inline TODOs, or unresolved structural directives directed at `agy` are strictly disallowed. If a part is required, a dedicated part specification must be instantiated immediately.

### 2.2 Dedicated Subpage Requirement (`parts/`)

* Every custom fabricated part must live at its own dedicated route and directory within the docs hierarchy:
```text
docs/
└── parts/
    └── <part-slug>/
        ├── index.md           # Markdown technical summary & specification
        ├── model.3ds          # Canonical 3D asset
        └── assets/            # Supporting isometric renders or dimension diagrams

```


* Shared or reused custom parts across stages (e.g., Stage 1 manual baseline up to Stage N automation) link directly back to this canonical slug instead of duplicating inline specs.

### 2.3 Required Subpage Contents

Each `index.md` for a custom-fabricated part must provide:

1. **Part Metadata Frontmatter**:
```yaml
id: "part-custom-<slug>"
title: "<Human-Readable Part Name>"
classification: "custom-fabricated"
fabrication_method: "3d-printed | machined | laser-cut | manual-stock"
material: "aluminum | copper | brass | glass | rubber | petg" # strictly zero-plastic/food-safe rules
model_file: "./model.3ds"
estimated_cost: 0.00
dimensions:
  x_mm: 0.0
  y_mm: 0.0
  z_mm: 0.0

```


2. **Markdown Technical Summary**:
* **Purpose & Functional Role:** Clear explanation of why off-the-shelf hardware cannot fulfill this role in the duckweed circulation/lighting loop.
* **Mating Interfaces & Tolerances:** Exact mating components (e.g., outer diameter of copper pipe, bolt hole pitch for servo mounts, continuous steel core anchors).
* **Fabrication & Post-Processing Instructions:** Print infill/wall settings, tap/thread sizes, deburring steps, or seal requirements.


3. **Interactive / Embed Asset:**
* Embedded WebGL/Three.js viewer tag pointing directly to `model.3ds` for in-browser visual inspection.
* Direct download link for `model.3ds`.
