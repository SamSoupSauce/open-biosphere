# [RFC-0011 / DOCS-003] Universal Vector SVG Blueprint Standard & Code Block Elimination

## 1. Executive Summary & Problem Statement
Prior iterations of the Open Biosphere technical documentation utilized plain-text code fences (```text or ```) containing ASCII-art box drawings to represent mechanical elevation profiles, electromechanical schematics, and system architectures. While convenient during early authoring, ASCII diagrams present severe shortcomings in production open-hardware documentation:
* **Mobile & Small-Screen Clipping:** Monospace ASCII diagrams cannot reflow and clip horizontally on mobile viewports, tablet screens, or narrow browser panes.
* **Lack of Zoom & High-DPI Clarity:** ASCII text cannot scale smoothly when builders zoom in to inspect dense wiring harnesses, pinouts, or mechanical tolerances.
* **Visual Inconsistency:** Monospace ASCII lacks visual hierarchy, contrast styling, and standardized color channels for power, ground, signal, and mechanical structures.
* **Search & Accessibility Ambiguity:** Screen readers and automated parsers misinterpret ASCII art characters (such as `┌`, `│`, `─`, `═`) as garbled punctuation rather than structured technical figures.

RFC-0011 mandates that **all engineering blueprints, kinematics profiles, wiring schematics, and system architecture diagrams must be authored and embedded as standalone Vector SVG (`.svg`) assets**. Raw code blocks are strictly forbidden for graphical diagrams and are restricted exclusively to executable code, configuration scripts, and data payloads.

---

## 2. Structural & Architectural Directives

### 2.1 The "Zero ASCII Blueprint" Invariant
* No technical drawing, mechanical elevation, electrical schematic, or system flow diagram may be enclosed within markdown code blocks (` ```text `, ` ``` `, or similar).
* Code blocks are reserved solely for executable code (Python, C++, Dart, JavaScript), machine-readable data files and schemas (JSON, YAML, INI), and shell command snippets (Bash).
* All legacy ASCII diagrams across system overview pages, RFC specifications, and machine hardware stage manuals have been eliminated and replaced with dedicated `.svg` vector files.

### 2.2 Standardized Vector SVG Palette & Styling
All generated blueprints adhere to the standardized Open Biosphere dark-mode engineering palette:
* **Background Fill**: `#0a0f1d` to `#030712` linear gradient with 30×30 mm `#1e293b` grid pattern.
* **Frames & Chassis**: `#334155` / `#64748b` outer structural borders and mechanical datum lines.
* **Mechanical / Active**: `#38bdf8` (Cyan) primary mechanical components and fluidic lines.
* **Electromechanical / Actuators**: `#f59e0b` (Amber) motors, stepper drivers, power buses, and clutches.
* **Sensors & Biomedia**: `#10b981` (Emerald) ultrasonic sensors, float switches, and duckweed mats.
* **Control / Reset**: `#3b82f6` (Blue) secondary logic and SD recovery interlocks.
* **Power Cut / Safety**: `#ef4444` (Red) master DC disconnect switches and 250ms deadman triggers.
* **Compute / Neural**: `#a855f7` (Purple) Central Controller, GGUF inference, and BLE virtual links.
