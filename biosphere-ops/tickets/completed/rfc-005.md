# [RFC-0005 / SYS-002] Physical Hardware Interlocks & Minimalist BLE Virtual Interface Standard

## 1. Executive Summary & Design Law
Physical control panels with dedicated jog buttons, dials, and forward/reverse switches are banned across all machine tiers. Physical panels add unnecessary BOM cost, introduce water ingress points, decay under high humidity, and cause priority contention ("control fights") between manual switches and autonomous loops.

All Open Biosphere nodes and tools must adhere to the **Strict Two-Control Physical Standard**:
1. **Physical Master Power Cut:** Inline hardware switch directly isolating DC supply (Solar/Battery/Rail).
2. **SD Factory Restore Button:** Dedicated tactile switch that triggers an automatic hardware re-flash from micro-SD storage, returning the board to factory baseline.

All interactive operation, calibration, jogging, and pairing are conducted via ephemeral Bluetooth Low Energy (BLE) using the Flutter companion app ("Virtual Panel").

---

## 2. Hardware Specification: The Two Physical Controls

### Control 1: True Hardware Power Disconnect
* **Placement:** Located directly on the master DC input line between power source (solar charge controller / battery / power brick) and the board.
* **Function:** Mechanically severs positive power. Zero soft-switches, zero sleep-state leakage. When OFF, the node and all connected peripherals are completely de-energized for maintenance.

### Control 2: The "Nuke & Pave" SD Reset Button
* **Placement:** Recessed tactile button on the node enclosure next to the status OLED.
* **Operation & Logic:**
  * Holding the button for 5 seconds during boot trips the secondary bootloader routine.
  * The bootloader reads the golden recovery image (`firmware.bin` and `config.default`) from the onboard micro-SD card.
  * Overwrites the internal flash memory and wipes NVS (Non-Volatile Storage) partitions clean.
  * Restores factory defaults: clears assigned Controller IDs, kills deadlocks or runaway loops, and re-initializes BLE in an unassigned, discoverable state.

## 3. Ephemeral BLE Interaction Pattern ("Virtual Panel")

Because each node and tool operates on an ESP32, the user interface lives dynamically inside the Flutter mobile companion app:


```

[ Operator with Phone ]
│
│  1. Walk up & BLE Pair
▼
┌──────────────────────────────────────────────┐
│       FLUTTER APP: "VIRTUAL PANEL"           │
│  • Reads Tool/Node Manifest via BLE GATT     │
│  • Displays dynamic controls for that unit:  │
│      - Forward / Reverse jog pads            │
│      - Speed / Flow sliders                  │
│      - Target Controller ID input box        │
│      - Live sensor telemetry stream          │
└──────────────────────────────────────────────┘
│
│  2. Execute configuration or jog
│  3. Disconnect & Forget
▼
[ Node commits settings, resumes autonomous work ]

```

### The Provisioning & Override Flow
1. **Commissioning:** 
   * Operator opens the Flutter app and scans for nearby unassigned nodes via BLE.
   * Tap target node (e.g., `SKIMMER-NODE-01`).
   * App presents an input field: *"Target Controller ID"*.
   * Operator types the 4-digit code displayed on the Central Pi 5's OLED.
   * Node saves the ID to NVS, initiates connection to the Controller's hidden Wi-Fi network, and unpairs BLE.
2. **Manual Jog / Maintenance Override:**
   * Need to purge an auger or test a pump? Open the app, pair to that node via BLE.
   * The app renders real-time jog buttons and telemetry gauges.
   * Perform the manual action.
   * Close the app or walk away. The BLE link drops, and the node returns to listening for commands from the Central Controller.

---

## 4. Remediation Directives for Documentation & Code
1. **Catalog Updates:** Purge all mentions of external IP67 button boxes, 10-turn analog potentiometers, and multi-switch jog panels from machine specifications.
2. **Hardware BOMs:** Update all Node/Tool BOMs to reflect:
   * 1x Heavy-Duty Inline DC Power Switch.
   * 1x Tactile Reset Button (Wired to SD recovery pin).
   * 1x Micro-SD card slot module (with 8GB/16GB recovery card pre-loaded with golden `.bin`).
   * 1x Mini status OLED (0.42" or 0.91" I2C).
3. **Firmware Guidelines:** Enforce the recovery bootloader routine and implement the standardized BLE GATT configuration service across all ESP32 firmware templates.
