# [RFC-0008 / DATA-001] Global Part Registry & Shared Bill of Materials Schema

## 1. Executive Summary & Problem Statement
Currently, parts and raw materials are hardcoded into isolated Markdown tables within individual machine stage documents. This causes duplicated part metadata, pricing inconsistencies, untracked shared components across multiple machines (e.g., standard NEMA steppers, 316L wedge-wire panels, Delrin pivot pins, ESP32 modules), and no centralized repository for CAD assets or sourcing links.

RFC-0008 establishes a **Global Part Registry (`parts/`)** and a standardized JSON/Frontmatter schema for discrete physical components. Every machine stage BOM will reference parts by canonical unique identifiers (`part_id`), enabling cross-machine dependency mapping, consolidated bill-of-materials generation, and direct downloading of fabrication files (STLs, glTF, STEP).

---

## 2. Directory Hierarchy & Registry Structure

A dedicated `parts/` content collection is established under `src/content/`:

```text
src/content/
├── docs/
│   └── parts/
│       ├── catalog.md                  # Interactive Global Part Registry & Search
│       ├── mechanical/                 # Extrusions, fasteners, bearings, shafts
│       ├── electrical/                 # Sensors, actuators, drivers, controllers
│       ├── fluidic/                    # Valves, pumps, nozzles, bulkheads, media
│       └── custom-fab/                 # 3D printed, laser cut, or welded assemblies
└── data/
    └── parts.json                      # Machine-readable single source of truth
public/
└── assets/
    └── parts/
        └── <part_id>/
            ├── photo.webp              # High-res physical part photo / render
            ├── model.gltf              # Canonical glTF 2.0 3D CAD asset (or .stl if printed/fabbed)

```

---

## 4. Machine Stage BOM Linking Specification

In each machine's `stage-X.md` file (established in RFC-0007), static markdown BOM tables are replaced with dynamic or linked references to the Global Part Registry.

### Rendering Directives for `stage-X.md`:

* Each BOM table row must link the part name directly to its registry page:
`[316L Wedge-Wire Screen Panel](/parts/fluidic/PART-MECH-WEDGE-150U/)`.
* The table must surface:
1. **Canonical ID** (`PART-MECH-WEDGE-150U`)
2. **Part Name & Brief Spec**
3. **Direct Supplier Link**
4. **Fabrication Type** (Stock / 3D Print / Custom Cut)
5. **Estimated Cost**
6. **Asset Link** (`[Download .glTF / STL]`)



---

## 5. Remediation Directives for `agy`

1. **Initialize Global Registry:** Create `src/content/docs/parts/` with subdirectories `mechanical/`, `electrical/`, `fluidic/`, and `custom-fab/`.
2. **Extract Parts from Catalog:** Ingest all hardcoded parts from the existing machine docs and map them into `src/data/parts.json`. De-duplicate shared parts across machines.
3. **Generate Static Part Pages:** Create individual markdown pages for each registered part rendering dimensions, procurement choices, supplier URLs, 3D asset download buttons, and a reverse-lookup list of machines that use that part.
4. **Update Stage BOMs:** Rewrite the BOM sections in all `stage-0.md`, `stage-1.md`, and `stage-2.md` files to bind directly to the new `part_id` registry.
