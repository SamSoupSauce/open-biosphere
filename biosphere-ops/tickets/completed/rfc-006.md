# [RFC-0006 / SOFT-001] Agnostic Controller Runtime & Host Specification

## 1. Executive Summary & Hardware Agnosticism
The Biosphere Controller is defined strictly as a **portable, hardware-agnostic software runtime**, not a proprietary physical appliance. Any compute host capable of hosting an isolated Wi-Fi Access Point and running Python with `llama-cpp-python` qualifies as a valid Biosphere Controller.

Acceptable host hardware targets include, but are not limited to:
* Dedicated single-board computers (Raspberry Pi 4/5, Orange Pi, Rockchip boards).
* Repurposed or off-lease x86_64 mini PCs / thin clients.
* Laptops running Linux or macOS (e.g. ThinkPad, Apple Silicon M-series).
* Workstations or home servers located within Wi-Fi range of the farm installation.

---

## 2. Minimum Host System Requirements
* **OS:** Linux (Debian, Ubuntu, Alpine, Arch) or macOS (12.0+).
* **Wireless NIC:** 802.11 b/g/n/ac Wi-Fi adapter with Access Point (AP/Master mode) support.
* **Compute:** 64-bit multi-core CPU (ARM64 or x86_64) with minimum 4GB RAM.
* **Python Runtime:** Python >= 3.10.
* **LLM / Inference Backend:** `llama-cpp-python` compiled with native hardware acceleration (Metal, OpenCL, CUDA, or AVX2).

---

## 3. Network Architecture & SSID Discovery Pattern

The host manages an isolated, local-only private network for subordinate Machine Nodes without requiring an external internet gateway or home router connection.

### AP Naming & Addressing Spec
* **SSID Convention:** `POTFRM-<CLUSTER_ID>`
  * `<CLUSTER_ID>`: A 4-digit numeric string (e.g., `POTFRM-4096`, `POTFRM-1024`).
* **Security:** WPA2/WPA3-PSK with a deterministic or locally configured passphrase.
* **Network Envelope:**
  * Subnet: `192.168.42.0/24`
  * Controller Static IP: `192.168.42.1`
  * Node DHCP Range: `192.168.42.10` to `192.168.42.250`
* **Local Discovery:** Emits an mDNS service advertisement: `_biosphere-controller._tcp.local.`

## 4. Software Stack & Core Daemons

The Controller runtime is composed of three lightweight, decoupled daemon layers:


```

┌────────────────────────────────────────────────────────┐
│               FLUTTER COMPANION APP                     │
│         (Connects via BLE or Local Wi-Fi)              │
└───────────────────────────┬────────────────────────────┘
│ WebSocket / REST API
▼
┌────────────────────────────────────────────────────────┐
│            CONTROLLER ORCHESTRATION DAEMON             │
│                 (Python 3.10+ AsyncIO)                 │
│  • Manages Node registry & tool command queues         │
│  • Schedules telemetry logging & harvest triggers      │
│  • 250ms periodic heartbeat dispatcher                 │
└─────────────┬────────────────────────────┬─────────────┘
│ Local API                  │ In-Memory IPC
▼                            ▼
┌──────────────────────────┐  ┌──────────────────────────┐
│   llama-cpp-python       │  │   WIRELESS MESH GATEWAY  │
│ Local GGUF Engine        │  │   (HostAP / dnsmasq)     │
│ • Vision-language eval   │  │ • 192.168.42.1 AP        │
│ • Closed-loop decisions  │  │ • Node UDP/TCP sockets   │
└──────────────────────────┘  └──────────────────────────┘

```

### 1. Wireless Mesh Gateway (`hostapd` / NetworkManager)
* Provisions the `POTFRM-<ID>` AP on boot.
* Runs lightweight DHCP/DNS service allocating static leases mapped to Node hardware MAC addresses.

### 2. Controller Orchestration Daemon (`biosphere-core`)
* Asynchronous event loop listening on port `8443` (WSS / HTTPS).
* Maintains the global state tree of all paired Nodes (`/nodes/{node_id}/tools`).
* Emits periodic heartbeats to all active Nodes.
* Exposes a stateless status API queried by the Flutter companion app over local Wi-Fi or local BLE bridge.

### 3. Inference Engine (`llama-cpp-python`)
* Loads quantized GGUF models (e.g., 1B–4B parameter lightweight models) for non-linear agricultural reasoning, anomaly detection, and vision parsing.
* Runs entirely locally on host compute—zero cloud calls, zero external subscription dependencies.

## 5. Provisioning & Headless Execution Flow

1. **Service Launch:** 
   * On headless machines, the daemon runs as a persistent `systemd` service (`biosphere-controller.service`).
   * On desktop/laptop workstations, the daemon can be run directly via CLI:
     ```bash
     biosphere-controller start --id 4096 --model models/mistral-7b-q4.gguf
     ```
2. **Identification Output:**
   * If an I2C/SPI OLED is attached, it renders `POTFRM-4096`.
   * If running headless without a screen, the ID is output to terminal stdout and advertised over BLE beacon for discovery by the Flutter app.
3. **Node Handshake:**
   * Nodes configured with target ID `4096` scan for `POTFRM-4096`, authenticate, obtain an IP lease, and register their available Tools via WebSocket handshake at `ws://192.168.42.1:8443/register`.
