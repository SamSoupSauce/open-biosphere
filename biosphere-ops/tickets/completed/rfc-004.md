# [RFC-0004 / ARCH-001] Controller-Node-Tool (CNT) Hierarchical Edge Architecture

## 1. Executive Summary & Philosophy
The current machine catalog incorrectly assumes each appliance hosts an isolated, high-tier compute node running standalone vision/planning and arbitrary monolithic CAN transceivers. 

This RFC establishes the **Controller-Node-Tool (CNT)** standard across the entire Open Biosphere system:
* **The Controller (Central Brain):** One physical black-box appliance orchestrating the entire biosphere enclosure.
* **The Node (Machine Subsystem / Aggregator):** One per physical machine (e.g., Fluidic Skimmer, Sprout Bioreactor), orchestrating that machine's immediate environment.
* **The Tools (Actuators & Sensors):** Minimalist edge micro-controllers dedicated to a single operational device (stepper, valve, float sensor, camera).

## 2. Structural Layer Definitions

### Layer 1: The Controller (Biosphere Master)
* **Hardware:** Raspberry Pi 5 (8GB) with dedicated NPU/AI Hat (e.g., Hailo-8 / Coral).
* **Physical Enclosure:** Self-contained black-box enclosure requiring only master DC power.
* **Display Interface:** Dedicated small I2C/SPI OLED display showing:
  * Controller Pairing ID (e.g., `CTRL_ID: 4096`).
  * System health, connected Node count, and Wi-Fi status.
* **Networking & RF:**
  * **Wi-Fi AP:** Broadcasts a hidden, high-throughput WPA3 local network for Nodes only.
  * **Bluetooth (BLE):** Dedicated service open for operator companion app connection. Operators connect their phone to the Controller via BLE to query global biosphere health, telemetry, yield statistics, and active alerts.

### Layer 2: The Node (Subsystem Manager)
* **Hardware:** Mid-tier ESP32 module (ESP32-S3 with PSRAM).
* **Topology Role:** Bridges the high-level Controller commands with low-level physical Tool execution.
* **Display Interface:** Dedicated mini OLED screen showing:
  * Node Name (e.g., `NODE: SKIMMER-01`).
  * Assigned Controller Pairing ID.
  * Active downstream Tool count and link state.
* **Networking & Provisioning:**
  * **Uplink:** Local Wi-Fi client connecting to Controller's hidden AP.
  * **Downlink:** Local BLE Central managing Tool peripheral connections.
  * **Provisioning Flow:**
    1. Builder presses the setup button on the Node.
    2. Builder connects mobile companion app to the Node over BLE.
    3. App prompts: *"Enter Target Controller ID"*.
    4. Builder inputs the ID displayed on the Controller's physical screen.
    5. Node commits the ID to NVS (non-volatile storage), associates with the hidden Controller Wi-Fi network, and executes the registration handshake.

### Layer 3: The Tool (Dedicated Hardware Edge Worker)
* **Hardware:** Minimalist micro ESP32 (e.g., ESP32-C3 / Xiao ESP32).
* **Scope:** Dedicated strictly 1:1 with an individual actuator, motor driver, or discrete sensor cluster. Tools never run heavy vision or cross-machine coordination.
* **Display Interface:** Micro OLED screen (0.42" or 0.91") indicating Tool Type, Tool ID, and Link Status (e.g., `TOOL: AUGER_DRV | LINK: OK`).
* **Fail-Safe & Watchdog:**
  * Implements an uncompromising **250ms hardware watchdog**.
  * If the Tool loses BLE connection to its Node for >250ms, it drops immediately into high-Z safe state: stepper outputs cut to zero holding torque, linear actuators stop in place, solenoid valves snap closed.

## 3. Provisioning & Operational Runbook

### Phase A: Controller Initialization
1. Connect master 12V/24V power to the Central Black Box.
2. Pi 5 boots, initializes AI runtime, brings up hidden Wi-Fi network, and displays pairing integer on its OLED: `ID: 4096`.
3. Open companion mobile app, pair with Controller via BLE, verify empty node tree.

### Phase B: Node Commissioning
1. Power up target machine Node (e.g., Skimmer Node).
2. Mini screen displays `NODE UNPAIRED - PAIR VIA BLE`.
3. Select Node in mobile app via BLE; enter `4096`.
4. Node pairs with hidden Wi-Fi, handshakes with Controller, and switches OLED to `ONLINE | LINK -> 4096`.

### Phase C: Tool Binding
1. Power up dedicated Tool controller.
2. Tool auto-advertises peripheral BLE service with its fixed Tool Descriptor (`DEV_PUMP_VFD`, `DEV_AUGER_STEP`, `DEV_SUMP_LEVEL`).
3. Machine Node automatically captures and binds its local Tools, routing command primitives from the Controller directly to the appropriate Tool edge.

## 4. Remediation Directives for `agy` (Catalog-Wide Rewrite)
1. **Strip Monolithic CAN & Onboard Pi Modules:** Remove Raspberry Pi CM4 and heavy AI blocks from individual machine pages. Machines are strictly **Nodes** hosting modular **Tools**.
2. **Update Add-On 2 Spec:** Replace the previous CAN-bus-only architecture in Add-On 2 with the **Node + Tool BLE/Wi-Fi stack**, mini I2C status screens, and Controller handshake protocol.
3. **Preserve Mechanical & Push-Button Foundations:** Base Machine (manual levers/cranks) and Add-On 1 (raw relays/buttons/slip-clutches) remain completely unchanged.
