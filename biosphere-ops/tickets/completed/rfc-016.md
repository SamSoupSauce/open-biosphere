# RFC-016: Comprehensive 3D Model Completeness & Explicit Spatial HUD Controls

**Status:** Completed (Implemented & Verified)

**Author:** Sam

**Target:** Open Biosphere Web Viewer (`three.js` / GLTF engine)

**Supersedes/Builds on:** RFC-007, RFC-008, RFC-010

---

## 1. Objective

This RFC establishes two foundational operational requirements for the Open Biosphere visual engine:

1. **Asset Rigor:** Mandating explicit 3D GLTF models for every catalog entry, including standard off-the-shelf stock hardware and electronic components (eliminating invisible nodes or bounding-box placeholders).
2. **Deterministic Camera Navigation:** Eliminating scroll wheel event binding (`wheel` listener) entirely to prevent accidental canvas hijacking and page scroll conflicts. Replacing implicit mouse gestures with a discrete, high-contrast on-screen HUD for Zoom, Rotation, and 3-Axis Translation.

---

## 2. Asset Integrity: Comprehensive Parts Modeling

Every Bill of Materials (BOM) entry referenced in `RFC-008` parts schemas must link to a valid `.gltf`/`.bin` bundle. Placeholders, null references, and dimension-only debug wireframes are deprecated.

* **Stock Hardware:** Fasteners, brackets, stainless steel / brass threaded rods, sanitary tri-clamp fittings, glass panes, rubber seals, and structural tubing must have real-geometry GLTF assets modeled to spec.
* **Electronics:** ESP32 node modules, sensor breakout boards (CO₂, O₂, humidity, pressure), terminal blocks, stepper motors, driver boards, and Raspberry Pi hat assemblies must include low-to-mid poly GLTF representations with true-to-life dimension envelopes and port orientations.
* **Standardization:** All models must export normalized to true millimeter scale with the origin aligned to their primary mating or mounting face.

---

## 4. HUD Navigation Architecture

The camera controls are consolidated into three explicit HUD clusters overlaid on the viewport:

```
+--------------------------------------------------------------------+
|  [VIEWPORT]                                                        |
|                                                                    |
|  [TRANSLATION D-PADS]               [ROOM SELECT]  [ROTATION COL]  |
|   Horizontal: [◄] [↔] [►]            | Room 01 |    [ ⟲ ]          |
|   Vertical:   [▲] [↕] [▼]            | Room 02 |    [ ⟳ ]          |
|   Depth:      [▲] [Z] [▼]            | Room 03 |    [  ▲  ]        |
|                                                     [  ▼  ]        |
|                                                                    |
|  [ZOOM CONTROLS]                                                   |
|   [ 🔍- ]  [ 🔍+ ]                                                 |
+--------------------------------------------------------------------+

```

### 4.1. Zoom Module

* **Placement:** Bottom-left or bottom-center docking.
* **Components:** Two distinct tactile buttons flanking the zoom state:
* **Zoom Out:** `[ 🔍- ]` (Spyglass icon with minus). Decrements field of view or scales camera distance along the view vector by $+step$.
* **Zoom In:** `[ 🔍+ ]` (Spyglass icon with plus). Increments field of view or scales camera distance along the view vector by $-step$.



### 4.2. Rotation Column (Docked with Room Buttons)

* **Placement:** Arranged in a unified vertical column directly adjacent to the Room Selection panel.
* **Controls:**
* **Yaw (Azimuth):**
* Counter-Clockwise: `[ ⟲ ]` (Step rotation around current target $+Y$).
* Clockwise: `[ ⟳ ]` (Step rotation around current target $-Y$).


* **Pitch (Elevation):**
* Tilt Up: `[ ▲ ]` (Step elevation pitch up toward zenith).
* Tilt Down: `[ ▼ ]` (Step elevation pitch down toward nadir).





### 4.3. Movement / Translation Module (3-Axis Camera Pan)

Replaces mouse-middle-click/drag panning with unambiguous, directional vector shifts:

* **Horizontal (X-Axis):**
* Icon Header: `↔` (Horizontal two-facing arrow) labeled **Horizontal**.
* Left: `[ ◄ ]` (Moves camera/target $-X$).
* Right: `[ ► ]` (Moves camera/target $+X$).


* **Vertical (Y-Axis):**
* Icon Header: `↕` (Vertical two-facing arrow) labeled **Vertical**.
* Up: `[ ▲ ]` (Moves camera/target $+Y$).
* Down: `[ ▼ ]` (Moves camera/target $-Y$).


* **Depth / Traverse (Z-Axis):**
* Icon Header: `⤢` / `Z` labeled **Depth / Axial**.
* Forward: `[ ▲ ]` (Translates camera along view forward vector $+Z$).
* Backward: `[ ▼ ]` (Translates camera along view reverse vector $-Z$).

## 5. Implementation Specification

### 5.1. UI State & Camera Control Bindings (TypeScript / Three.js)

```typescript
export interface CameraStepConfig {
  panStep: number;      // World units per click (default: 50mm)
  zoomStep: number;     // Distance delta per click (default: 100mm)
  rotateStep: number;   // Radians per click (default: Math.PI / 12)
}

export class BiosphereCameraController {
  private camera: THREE.PerspectiveCamera;
  private target: THREE.Vector3;
  private config: CameraStepConfig;

  constructor(camera: THREE.PerspectiveCamera, target: THREE.Vector3, config?: Partial<CameraStepConfig>) {
    this.camera = camera;
    this.target = target;
    this.config = {
      panStep: 50,
      zoomStep: 100,
      rotateStep: Math.PI / 12,
      ...config
    };
  }

  // --- ZOOM ---
  public zoomIn(): void {
    const dir = new THREE.Vector3().subVectors(this.target, this.camera.position).normalize();
    this.camera.position.addScaledVector(dir, this.config.zoomStep);
  }

  public zoomOut(): void {
    const dir = new THREE.Vector3().subVectors(this.target, this.camera.position).normalize();
    this.camera.position.addScaledVector(dir, -this.config.zoomStep);
  }

  // --- ROTATION (Vertical Row) ---
  public rotateYaw(direction: 1 | -1): void {
    const offset = new THREE.Vector3().subVectors(this.camera.position, this.target);
    const angle = direction * this.config.rotateStep;
    offset.applyAxisAngle(new THREE.Vector3(0, 1, 0), angle);
    this.camera.position.copy(this.target).add(offset);
    this.camera.lookAt(this.target);
  }

  public rotatePitch(direction: 1 | -1): void {
    const offset = new THREE.Vector3().subVectors(this.camera.position, this.target);
    const right = new THREE.Vector3().crossVectors(new THREE.Vector3(0, 1, 0), offset).normalize();
    const angle = direction * this.config.rotateStep;
    offset.applyAxisAngle(right, angle);
    this.camera.position.copy(this.target).add(offset);
    this.camera.lookAt(this.target);
  }

  // --- TRANSLATION ---
  public panHorizontal(direction: 1 | -1): void {
    const right = new THREE.Vector3();
    this.camera.getWorldDirection(new THREE.Vector3());
    right.crossVectors(this.camera.up, this.camera.getWorldDirection(new THREE.Vector3())).normalize();
    const delta = right.multiplyScalar(direction * this.config.panStep);
    this.camera.position.add(delta);
    this.target.add(delta);
  }

  public panVertical(direction: 1 | -1): void {
    const delta = new THREE.Vector3(0, direction * this.config.panStep, 0);
    this.camera.position.add(delta);
    this.target.add(delta);
  }

  public panDepth(direction: 1 | -1): void {
    const forward = new THREE.Vector3();
    this.camera.getWorldDirection(forward);
    forward.y = 0; // Pure planar ground push
    forward.normalize();
    const delta = forward.multiplyScalar(direction * this.config.panStep);
    this.camera.position.add(delta);
    this.target.add(delta);
  }
}

```

## 6. Verification & Pass Criteria

1. **Wheel Isolation:** Scrolling anywhere inside the 3D viewport canvas produces zero camera movement and does not prevent normal parent document scrolling.
2. **Deterministic Camera Bounds:** Clicking each directional button increments camera state by fixed, predictable steps without continuous runaway drift.
3. **No Empty Geometry:** Inspecting any BOM entry in the stage assembly highlights a valid mesh; zero parts register as zero-sized primitives or missing node definitions.
