# [RFC-0007 / DOCS-001] Multi-Stage Machine Sub-Page Architecture & Assembly Template

## 1. Executive Summary & Problem Statement
Currently, each open-hardware machine specification is consolidated into a single monolithic document containing all build tiers (Base, Semi-Autonomous, Autonomous). This creates cognitive overload, makes stage-specific bills of materials difficult to parse, and clutters the reading flow for builders executing a specific tier.

RFC-0007 mandates that every machine catalog entry be decomposed into a dedicated parent overview page and discrete, sequential sub-pages for each operational stage.

---

## 2. Directory Hierarchy & Routing Spec

Every machine under `src/content/docs/hardware/<machine-slug>/` must be restructured into the following directory format:

```text
hardware/<machine-slug>/
├── index.md        # Subsystem Overview, Target Crops, and Stage Comparison Matrix
├── stage-0.md      # Base Zero-Power Machine (Pure Mechanical Baseline)
├── stage-1.md      # Add-On 1: Electromechanical Pack (BLE Virtual Panel & DC Drive)
└── stage-2.md      # Add-On 2: Agentic Autonomous AI Pack (Controller-Node-Tool Mesh)

```

### Starlight Navigation Interlock

* The Starlight sidebar group for each machine should expand to expose the parent overview and all three discrete stages.
* Linear bottom pagination (`pagination: true`) or custom stage-nav buttons must link directly between:
`Overview -> Stage 0 -> Stage 1 -> Stage 2`.

---

## 3. Standardized Sub-Page Content Template

Every `stage-X.md` file must strictly follow this standardized 6-part anatomy:

### Part 1: Stage Header & Executive Summary

* **Title:** Full machine name with stage identifier (e.g., `# Fluidic Skimmer — Stage 0: Zero-Power Baseline`).
* **Summary Box:** Concise paragraph defining the operational scope, expected throughput, power requirement, and cost ceiling.

### Part 2: Capability Delta (Features Introduced)

* A dedicated callout box or list explicitly outlining what this stage adds over the previous tier:
* For **Stage 0:** Fundamental mechanical capabilities, gravity flow, zero-power operation.
* For **Stage 1:** Electromechanical drive, elimination of manual hand-cranking, BLE virtual panel jogging, preserved manual fallback.
* For **Stage 2:** Controller-Node-Tool telemetry integration, autonomous closed-loop vision/sensors, zero-touch harvesting cycles.



### Part 3: Isolated Stage Bill of Materials (BOM)

* Dedicated table listing *only* the parts needed to construct this stage (or upgrade to it).
* Must include part name, detailed specification, sourcing recommendation, and estimated USD cost.
* Footer line displaying:
* **Direct Stage Cost:** (e.g., `+$160.00`)
* **Cumulative Machine Investment:** (e.g., `$340.00 Total`)



### Part 4: Standalone Full SVG Blueprint

* An embedded, high-contrast, scalable vector blueprint (`.svg`) illustrating the machine strictly at this stage's level of completion.
* Diagrams must clearly indicate mechanical linkages (Stage 0), electrical/power topologies (Stage 1), or network/sensor overlays (Stage 2).

### Part 5: Step-by-Step Assembly & Operating Protocol

* Sequential step blocks (`### Step X.1`, `### Step X.2`, etc.) covering:
1. Mechanical mounting / retrofit operations.
2. Fluidic, power, or signal connections.
3. Pre-flight verification runbook and calibration tests.



### Part 6: Guided Stage Navigation Footer

* Interactive previous/next stage link buttons providing seamless forward and backward transitions:
* Example: `[← Stage 0: Zero-Power Baseline] | [Stage 2: Agentic Autonomous Pack →]`



---

## 4. Remediation Directives for `agy`

1. **Decompose Catalog:** Break each existing machine markdown file into a directory structure containing `index.md`, `stage-0.md`, `stage-1.md`, and `stage-2.md`.
2. **Isolate BOMs:** Split the consolidated BOM tables so each stage page lists only its required parts and tracks the cumulative sum.
3. **Generate Stage SVGs:** Ensure dedicated SVG diagrams are created and linked for each individual stage sub-page.
4. **Update Parent Overview:** The `index.md` for each machine must act as a clear comparison landing page with links leading directly into the Stage 0 guide.
